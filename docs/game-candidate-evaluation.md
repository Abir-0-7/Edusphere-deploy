# Game candidate evaluation — 2026-11-18

On 2026-11-18 the user requested designs while implementation stayed gated for
learner-demand evidence. On 2026-11-19 the user explicitly requested that all seven
candidates below be included as playable games, superseding that implementation
hold. The bounded authored practice slices are documented in `game-expansion.md`.
This authorization is not learner-demand evidence or human editorial approval.
All practice is free to enter. Game scores measure engagement, never career
readiness or independent mastery. The table retains the original evaluation plan;
its demand/capacity observations remain open research and release checks.

| Candidate                          | Objective and bounded content                                    | Deterministic grading proposal                                                                                                    | Accessible release journey                                                                     | Demand / capacity gate                                                                                     |
| ---------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Debugging Detective / Debug Quest  | Recognize one bug in a fixed reviewed Python snippet             | Choose the faulty line and a reviewed repair ID; server-held key, explanation and regression fixture; no arbitrary code execution | Instructions → line list → repair options → feedback/source → retry/resume; keyboard and touch | Await observed learner requests and usability sessions; promote one small non-executing defect family only |
| SQL Detective / Query Quest        | Reason about SELECT/filter/join results on tiny immutable tables | Reviewed query/result choices; reject execution variants until containment evidence                                               | Real DOM tables with headers and text alternatives; wrong/right/source/retry                   | No demand evidence; benchmark fixtures and server answer keys before coding                                |

| Proof Builder                      | Order a short proof with explicit assumptions                    | Validate a reviewed dependency DAG of proof steps and allowed equivalent orders                                                   | Ordered step list, move buttons, explanation, undo and resumable attempts                      | Requires reviewed proof bank plus observed demand; no LLM as sole judge                                    |

| Exam Escape                        | Apply concepts across a bounded sequence of puzzles              | Reviewed finite-state transitions and keys; no speed-based knowledge penalty                                                      | Pauseable reading, progress list, manual navigation and retry                                  | Need demand and content breadth; measure session memory/latency first                                      |

For each candidate, collect consented learner requests/observations, publish the
objective and minimum content/rubric fixtures, test ambiguity and useful incorrect
feedback, run the complete keyboard/touch win/loss/retry/restore journey, and measure
capacity on the existing free stack. Then promote one named implementation slice
under its Phase 8G task. Broader content, arbitrary code execution, calibrated
adaptive assessment and production readiness remain separate from this initial
user-authorized implementation.
